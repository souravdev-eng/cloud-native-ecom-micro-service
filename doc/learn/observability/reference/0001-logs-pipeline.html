Logs pipeline cheat sheet

The path

auth: logger.warn(...)          common/src/observability/logger.ts
  → process.stdout (1 JSON line)
  → Kubernetes container log
  → Alloy DaemonSet             k8s/observability/alloy.yml
      stage.json                reads level, service, trace_id
      stage.labels              labels: level, service  (only these)
      stage.structured_metadata trace_id, pod, namespace
  → Loki  (single binary, PV, 168h retention)   k8s/observability/loki.yml
  → Grafana Explore             k8s/observability/grafana.yml

Log line schema

timestamp, level, service, version, environment
Always present, stamped by the logger, and can't be overwritten by callers.
trace_id, span_id
Present only when the line is logged inside a span (ticket 03).
message
The human sentence.
error
{ name, message, stack } when an Error is logged.
anything else
Your structured fields, redacted.

Rule of thumb: label or not?

Make it a label only if it has a small, fixed set of values and identifies the log's source. Everything else goes in the line body (filter with | json) or in structured metadata.

LogQL

{service="auth-service"}                          # select a stream
{service="auth-service", level="warn"}            # narrow by label
{service="auth-service"} |= "Login failed"        # substring line filter
{service="auth-service"} | json | reason="wrong_password"
{service=~"auth-service|cart"} | json | level="error"

Knobs

LOG_LEVEL
Minimum level (error, warn, info, http, verbose, debug, silly). Set in k8s/config/app-config.yml.
LOG_FORMAT
json or pretty. The cluster forces json because it runs NODE_ENV=development.

Open Grafana

kubectl port-forward svc/grafana-srv 3300:3000
kubectl get secret ecom-secret -o jsonpath='{.data.GRAFANA_ADMIN_USER}' | base64 -d

Known gap

common/src/middleware/errorHandler.ts uses console.log(err). Its stack traces arrive as unstructured lines under {service="auth"}, with no redaction and no trace_id.
