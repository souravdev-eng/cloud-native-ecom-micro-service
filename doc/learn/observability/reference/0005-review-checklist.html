Reference · For PRs on tickets 04–18

Review checklist

Each item is a mistake that fails silently: nothing errors, and the telemetry just gets worse or unsafe. That's why a reviewer has to catch it.

Logs

  1. No new console.log. It bypasses redaction, JSON and trace_id. Use the shared logger. (L3)
  2. No new Loki labels with many values. Only level and service. IDs go in the line or in structured metadata. (L1)
  3. Secrets have secret-looking names. A new sensitive field that doesn't match the deny list needs a word in sensitiveKeys.ts plus a test. (L3)
  4. The cluster stays on LOG_FORMAT=json. Pretty output breaks Alloy's labels and the log → trace link. (L6)

Traces

  1. import './tracing' is the first line of the entry file. (L5)
  2. The bootstrap comes from @ecom-micro/common/telemetry, not the main entry, which loads Express. (L5)
  3. One service name: createLogger({ service }) equals startTelemetry({ serviceName }). (L6)
  4. Incoming traceparent is continued, never overwritten. For AMQP, context goes in headers, not payloads. (L5, ADR 0001)
  5. Batch processor in production. Simple is for the test seam only. (L6, L8)
  6. No new resource detectors that record the command line or env. Resource attributes aren't redacted. (L6)

Safety and architecture

  1. Nothing on the request path waits for telemetry. No awaits on export, no synchronous network calls. (L6)
  2. Services talk only to Alloy, never to Loki, Tempo or Prometheus directly. No Elasticsearch for telemetry. (ADR 0001)
  3. New cross-cutting telemetry lives in common and ships with a version bump; each consumer is bumped. (ADR 0001, CLAUDE.md)

Grafana and Alloy config

  1. $$ in Grafana provisioning variables ($${__tags}), or Grafana expands them from the environment and they come out empty. (L6)
  2. Follow the forward_to/output chain end to end. A component nobody forwards to does nothing. (L2)
  3. Requests and limits are set on new observability workloads (a ticket 02 criterion).

Tests

  1. They assert on outputs (channel calls, exported spans, stdout, headers), not on private fields. (L7)
  2. Seams don't skip the code under test. For example, the test exporter must still go through the redactor. (L7)
  3. "Nothing is sent" tests have a positive control. (L7)
